# Pulsewell Frontend

<img width="1893" height="896" alt="Screenshot 2026-09-17 131107" src="https://github.com/user-attachments/assets/0f0e2e3c-560e-4f0f-9e68-8631684f9ac1" />

Frontend for the Pulsewell music recommendation system.
The application allows users to sign in, choose a mood or medical condition and receive music recommendations generated by the backend.

## Technologies

- Next.js
- React
- TypeScript
- Firebase Authentication
- Tailwind CSS
- shadcn/ui
- Lucide React
- Zod
- React Hook Form

## Main Features

- Email and password registration
- Email and password login
- Google login
- Firebase authentication
- Mood-based music recommendations
- Medical condition-based recommendations
- Search history
- BPM and track duration display
- Album artwork
- Matched effect display
- Related symptoms display
- Responsive interface
- Loading and empty states

## Authentication

Firebase Authentication is used on the frontend.

Supported login methods:
- Email and password
- Google

After the user signs in with Firebase, the Firebase ID token is sent to the backend:
```text
POST /api/auth/sign-in
```

Authenticated backend requests use the Firebase token in the Authorization header.

## Recommendation Types

### Mood

Users can choose a mood and request music recommendations.

Mood results can include:
- title
- artist
- BPM
- duration
- artwork

### Medical Condition

Medical condition recommendations also include:
- matched effect
- related symptoms

Example:
```text
Track Name
Effect: RelaxationEffect
Symptoms: SleepDifficulty, Restlessness
90 BPM
3:24
```

## Environment Variables

Create a `.env.local` file in the project root.
```env
NEXT_PUBLIC_FIREBASE_API_KEY=
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN=
NEXT_PUBLIC_FIREBASE_PROJECT_ID=
NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET=
NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID=
NEXT_PUBLIC_FIREBASE_APP_ID=
NEXT_PUBLIC_FIREBASE_MEASUREMENT_ID=

NEXT_PUBLIC_AUTH_API_BASE_URL=
NEXT_PUBLIC_RECOMMEND_API_BASE_URL=
```

Do not commit `.env.local` to Git.

## Backend

The frontend requires the Spring Boot backend to be running.
Make sure the backend is available before using authentication, recommendations or search history.

## Installation

Install dependencies:
```bash
npm install
```

## Development

Run the development server:
```bash
npm run dev
```

Open:
```text
http://localhost:3000
```

## Build

Create a production build:
```bash
npm run build
```

Run the production build:
```bash
npm start
```

## Main Pages

The main player page allows the user to:
- choose a mood or medical condition
- choose the requested number of recommendations
- view recommendation results
- view BPM and duration
- view medical recommendation details

The account menu shows information about the authenticated Firebase user.
The search history section allows previous searches to be viewed and repeated.

## Notes

Firebase manages the authenticated session.
The frontend does not store Firebase authentication tokens manually in local storage.

Recommendation results depend on the data returned by the backend and Audius.

The number of returned recommendations may be lower than the requested limit if there are not enough tracks matching the selected criteria.
